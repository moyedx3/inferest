# 51 · 에이전트 추론 결제 레일

_에이전트가 자기 추론비를 자기 지갑에서 낸다 · 잔액은 기다리는 동안 이자를 벌고, 원금에는 닿지 않는다 · 공급은 오픈웨이트, 우리는 경로에 앉는다_

**작성 2026-09-24 · 🟢 출처 있는 사실 · 🟡 내 판단(미검증) · 🔴 불리한 확정 사실**

## 0. 세 줄

1. ⭐ **선불 블록이 아니라 잔액이다.** 지갑에 돈이 있고, 놀면 이자가 붙고, 에이전트가 쓰면 거기서 나간다. **만료도 소비 의무도 없다** — [[Touchmark]]형 블록의 문제(20% 할인 → 80% 소진)가 구조적으로 사라진다
2. ⭐⭐ **시장은 하나의 축이다 — "에이전트가 자기 지갑에서 추론비를 낸다."** 회사 트레저리든, 금융 에이전트 플랫폼이든, 개인이 물린 에이전트든 **같은 레일의 다른 크기**다
3. 🔴 **천장은 토큰이 아니라 달러다.** 오픈웨이트가 토큰의 약 1/3인데 **기업 지출에서는 11%**다. 우리 마진은 달러에 붙는다

---

## 1. 한 문단

> 온체인에 자금을 둔 조직과 사람은 이미 잔액에서 4~7%를 받고 있다. 그런데 **그 돈으로 AI 비용을 낼 방법이 없다.** 멀티시그에는 카드를 못 꽂고, 오프램프하려면 은행과 법인이 필요하고, DAO는 법인이 아예 없기도 하고, **지갑을 가진 에이전트는 애초에 카드를 만들 수가 없다.** 우리는 스위치 하나를 더한다. **켜면 추론비가 그 잔액에서 바로 나가고, 덜 쓴 달은 그냥 이자가 쌓인다.** 선불도 약정도 소멸도 없다. 뒤에서는 **오픈웨이트 모델**로 라우팅해 원가를 낮추고, 어려운 판단만 위 등급으로 올린다. **모델이 싸질수록 우리 마진이 넓어진다.** 그리고 지출 한도는 약속이 아니라 **코드**다 — 에이전트는 자기가 번 것만 먹고 원금에는 닿지 못한다.

## 2. 상품

```
   ① 지갑(멀티시그·EOA·에이전트 지갑)에서 볼트에 USDC 예치
        ⭐ 고객 명의 유지. 우리는 수탁하지 않는다
   ② OpenAI 호환 API 키 발급  →  base_url만 바꾸면 끝
   ③ 유휴 잔액에 이자. 사용량은 주기적으로 잔액에서 차감
   ④ 지출 정책(한도·팀별 배분·원금 불가침)은 온체인에서 강제
```

**핵심 차별점 셋**

| | |
|---|---|
| ⭐ **블록이 아니라 잔액** | 만료 없음 · 소비 의무 없음 · 기다리는 동안 이자 |
| ⭐ **지갑이 결제 주체** | 오프램프·카드·법인이 필요 없다 |
| ⭐⭐ **지출 정책이 코드** | 약속이 아니라 규칙 |

> 📌 [[Touchmark]]에서 **라우터·계량·상업 당사자 한정·실물 인도는 가져오고, 10억 토큰 블록과 만료는 버린다.** 잔액이 블록을 대체하고, 모든 면에서 낫다.

## 3. 왜 지금 · 왜 온체인

| | |
|---|---|
| 🟢 **에이전트 토큰이 사람 토큰을 넘었다** | **2026-02-01경** (OpenRouter, Ornn 논문 §4) |
| 🟢 **에이전트 워크로드가 오픈웨이트에 맞는다** | *"장기 에이전트·배치 평가·강화학습은 **지연을 견디고 하드웨어에 무관하다**"* |
| 🟢 **값 차이가 크다** | Ornn 표 4, 문턱 53~57: 오픈 **$0.09** vs 폐쇄 **$0.43** = **4.78배** |
| ⭐⭐ **에이전트는 카드를 못 만든다** | **이게 "왜 온체인이어야 하나"에 대한 반박 불가능한 답이다** |
| 🟢 **온체인 트레저리 수익은 이미 표준 기능** | Deel Earn류. **새로 설득할 게 없고 토글 하나다** |

## 4. ICP — 하나의 축, 세 크기

```
   시장 = "에이전트가 자기 추론비를 자기 지갑에서 낸다"

   공통:  ① 지갑이 결제 주체  ② 오픈웨이트가 주력  ③ 간헐적 사용
          ④ 카드를 못 쓰거나 쓰기 싫다  ⑤ 놀 때 이자
```

| | 누구 | 이자 기반 | 상태 |
|---|---|---|---|
| ⭐ **ICP1** | **온체인 트레저리를 가진 회사·DAO** | 트레저리 | ✅ **여기서 시작.** 명단을 만들 수 있다 |
| ⭐⭐ **ICP2′** | **금융 에이전트 플랫폼** (B2B) | **AUM** | 🟡 구조는 제일 잘 맞는데 시장이 얇다 |
| **ICP2** | **개인이 물린 에이전트** | 개인 잔액 | 🟡 부분 커버로는 성립 |

### ICP1 — 통증을 정확히

⚠️ *"오프램프가 어렵다"*는 절반만 맞다. 자금 받은 회사는 법인·은행이 있다. **진짜 통증은 이것:**
- 트레저리는 멀티시그에서 놀고, **옮기려면 거버넌스·서명 이벤트**
- 그런데 **AI 청구서는 운영 현금에서 나가 런웨이를 깎는다**
- 직원들이 각자 카드로 긁어 **귀속과 한도가 없다**
- 🔴 **DAO는 법인이 아예 없기도 하다**

### ICP2′ — 숫자가 편하다

**운용자산 $1M, 이자 5% → 연 $50,000**

| 에이전트 강도 | 연 추론비 | 이자 대비 | **AUM 대비** |
|---|---|---|---|
| 가볍게 (시간당) | ~$175 | 0.35% | 0.02% |
| **보통** (5분마다 + 분석) | **~$3,150** | **6.3%** | ⭐ **0.32%** |
| 무겁게 | ~$20,000 | 40% | 2.0% |

> ⭐ **0.32%는 액티브 펀드 보수율 정상 구간이다.** 금융 하는 사람에게 설명이 필요 없는 숫자다.

### ICP2 — 개인도 생각보다 크다

**GLM-5.3-Flash로 상시 돌리는 에이전트:** 월 출력 5,000만 × $0.50/M + 입력 3억 × $0.15/M = **월 $70** (Cursor 구독보다 크고, 전부 오픈웨이트다)

| 파킹 잔액 (5%) | 커버 |
|---|---|
| $5,000 | 30% |
| $17,000 | 100% |

🟡 **완전 커버는 빡세지만 "공짜"가 아니어도 팔린다.** 그리고 개인에겐 이자보다 **"에이전트에게 지갑과 한도를 준다"**가 더 큰 값어치일 수 있다.

## 5. ⭐⭐ 대사 규칙 — 원금 불가침

```
   기간 수익 Y,  추론비 C

   C ≤ Y   →  먹고, 남은 건 복리로
   C > Y   →  🔴 예산이 Y로 깎인다. 느려지거나 멈춘다
              원금은 절대 안 닿는다
```

**2단 배급**

| | |
|---|---|
| **기본 배급** | 패시브 이자의 일부 — 굶지 않게, 콜드스타트 해결 |
| ⭐ **추가 배급** | **초과수익의 일부 — 잘하면 더 먹는다** |
| 🔴 **원금** | **절대 안 닿는다** |

> ⭐⭐⭐ **이게 상품의 안전 속성이자 세일즈 포인트다.** 에이전트 플랫폼이 유저에게 제일 하고 싶은 말이 *"이 놈이 당신 원금을 태울 수 없습니다. 코드로."*
> **그리고 오프체인에서는 강제가 안 된다.** 47번 §3의 "관문(gate)"이 여기서 제일 깨끗하게 성립한다.
>
> ⚠️ **정직하게:** 패시브 이자는 에이전트가 번 게 아니다(자산이 번 것). *"일해서 밥값"*에 해당하는 건 초과수익 쪽이고, 그건 측정이 지저분하다.

## 6. 공급 — 오픈웨이트 한정과 그 경계

| 단계 | 공급 | 폐쇄형 | 마진 |
|---|---|---|---|
| **v0** | 오픈웨이트 **도매 구매** | 🔴 없음 | 얇다 · 인프라 0 |
| **v1** | 오픈웨이트 **자체 호스팅** | 🔴 **여전히 없음** | ⭐ 크다 |
| **v2** | + 우리 계정으로 폐쇄형 대리 | ✅ | 🟡 *"제품이냐 재판매냐"* |

> 🔴 **팹리스가 돼도 Claude/GPT는 못 준다.** 가중치가 안 나와 있다. **팹리스는 오픈웨이트 마진 축이고 폐쇄형은 계약 축이다. 직교한다.**
>
> ⭐ **그리고 v0에서 폐쇄형이 없어도 되는 이유:** 회사의 AI 지출은 이미 쪼개져 있다. **프리미엄 대화형은 Claude·GPT로, 에이전트·배치·RAG는 오픈웨이트로.** 우리는 후자만 받는다. **볼륨은 거기가 크다.**
>
> 🔴 **한계:** Ornn 표 4 — **문턱 ≥61에는 오픈 적격 모델이 없다.** 폐쇄 프런티어가 오픈보다 6점 위다. **그 위는 못 건드린다.**

**"제품이냐 재판매냐"의 선 (v2로 갈 때):** Cursor·Perplexity처럼 **자기 제품 안에서 API를 호출**하면 정상이고, [[Orbio]]처럼 **같은 API를 그대로 싸게 되팔면** 재판매다. 🟡 우리 물건이 어느 쪽인지는 **얇기**에 달렸다. 지출 정책·한도·귀속·등급 라우팅이 있으면 제품 쪽이다.

## 8. 기술 — 어려운 건 온체인이 아니다

| 부품 | 난이도 |
|---|---|
| 라우터·계량 (OpenAI 호환 프록시) | 🟢 낮다. 오픈소스 위에 |
| 금고 연동 (**Safe 모듈** 또는 `approve` 한도) | 🟢 낮다. 표준 |
| 수익원 (**ERC-4626**) | 🟢 낮다 |
| 주기 정산 배치 | 🟡 중간 |
| 🔴 **오픈웨이트 자체 호스팅** | 🔴 **높다** (v1) |

### ⭐⭐ 핵심 설계: 수탁하지 않는다
고객 자금은 **고객 Safe·고객 명의 볼트 포지션**에 그대로 있고, 우리는 **계량한 사용량만큼 끌어올 한도**만 갖는다. **이자도 고객 것이다.** → 🟡 수탁·자금이전 규제를 대부분 회피 (법률 확인 필요)

### 🔴 진짜 제약 셋
1. ⭐ **요청당 온체인 결제는 불가능하다** (가스·지연) → **오프체인 계량 + 주기 정산.** 그 사이 우리가 신용을 준다. 완화: 짧은 주기 + 선충전 버퍼. 🟡 예외: 에이전트 지갑은 x402류로 요청당이 실제로 된다
2. ⭐⭐ **즉시 상환 제약이 수익률 상단을 자른다** — sUSDS·Aave **4~5% 즉시** vs [[USD.AI]] **7.02%인데 QEV 큐** · GAIB **30일 쿨다운**. **해법은 2단 구조**(즉시 버퍼 + 수익 계층)지만 *"4~7%"*의 위쪽은 바로 못 쓴다
3. **계량 분쟁** — 요청별 감사 로그 필요. ⚠️ 우리가 계량 주체이자 판매자다

### v0에서 **안 만드는 것**
❌ 자체 볼트·수익 전략 · ❌ 수탁 · ❌ 멀티체인 · ❌ 자체 GPU 호스팅 · ❌ 폐쇄형 재판매

## 9. 🔴 이걸 죽이는 것

| # | | |
|---|---|---|
| **1** | ⭐⭐ **토큰은 많은데 달러가 적다** | 오픈웨이트가 **토큰의 1/3인데 기업 지출의 11%**(Menlo, 2024년 19%에서 하락). Ornn: *"저가 모델은 지출에서보다 토큰에서 더 큰 몫을 차지할 수 있다."* **우리 마진은 달러에 붙는다** |
| **2** | **시장 크기·타이밍** | 온체인 트레저리 + 유의미한 AI 지출의 교집합이 좁다. 에이전트 지갑이 늘면 넓어진다 — **타이밍 베팅** |
| **3** | **폐쇄형 커버리지 부재** | 고객이 *"전부 한 곳에서"*를 원하면 v0가 반쪽이다 |
| **4** | 🔴 **공급 경쟁** | v1로 가면 $4~5B짜리 팹리스들과 같은 링 |
| **5** | **수익률 위험이 고객에게** | 디페그·수익 급락 시 *"공짜 AI"*가 멈춘다 |
| **6** | ⚠️ **Deel·Mercury가 붙이면** | 🟡 그쪽은 추론 공급이 없다 → 경쟁이 아니라 **제휴 동작** |
